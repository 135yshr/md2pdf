# Example: Detailed Design Document

A realistic technical design document showcasing **English text mixed with
Japanese**, Mermaid diagrams (flowchart, sequence, ER), tables, code blocks
(Go / SQL / JSON / shell), and quoted reviewer comments.

This is the kind of document a consulting firm or in-house platform team
would write for an internal review. Use it to evaluate how md2pdf handles
real-world technical writing.

## Contents

- `input.md` — Source Markdown
- `output.pdf` — PDF generated by md2pdf (committed to the repo)

## What this example demonstrates

- ✅ English headings with Japanese phrases inline
- ✅ Mermaid **flowchart** (system component diagram)
- ✅ Mermaid **sequence diagrams** (login + token refresh flows)
- ✅ Mermaid **ER diagram** (data model)
- ✅ GitHub-flavored Markdown tables (mixed English / Japanese)
- ✅ Fenced code blocks: Go (with Japanese comments), SQL, JSON, shell
- ✅ Block quotes simulating reviewer comments (`> 田中: ...`)

## Generate the PDF yourself

```sh
md2pdf examples/01-design-doc/input.md -o examples/01-design-doc/output.pdf
```

Custom options that work well for design docs:

```sh
md2pdf \
  -page-size A4 \
  -margin-top 20mm -margin-bottom 20mm \
  -margin-left 16mm -margin-right 16mm \
  examples/01-design-doc/input.md
```
